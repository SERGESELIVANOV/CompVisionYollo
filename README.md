## Разбор библиотек, которые были рассмотрены ##

### ONNX Runtime ###

ONNX Runtime — высокопроизводительный рантайм для запуска моделей в формате ONNX на разных платформах и устройствах. Основные преимущества: промежуточный формат модели (ONNX) позволяет переносить обученные модели из PyTorch, TensorFlow и других фреймворков; поддержка аппаратных ускорителей (CUDA, TensorRT, DirectML, OpenVINO и др.); богатые API на C, C++ и Python; гибкая конфигурация сессий и оптимизаций.

Инструкцию по установки библиотеки в проект можно найти на сайтах: 
* Официальная документация и инструкции по установке: https://onnxruntime.ai
* Руководство по сборке и использованию C++ API: https://onnxruntime.ai/docs/build/

ONNX Runtime задумывался как универсальный инструмент для запуска моделей в формате ONNX, но как показала практика использования часто оставляет противоречивые впечатления. С одной стороны, он действительно предоставляет возможность работать с моделями, экспортированными из разных фреймворков, и поддерживает множество аппаратных ускорителей. Однако на практике настройка этой библиотеки оказывается довольно капризной: необходимо тщательно подбирать версии, следить за совместимостью с драйверами и дополнительными зависимостями, а подключение провайдеров вроде CUDA или TensorRT требует отдельной конфигурации и зачастую вызывает ошибки, если окружение настроено не идеально.

Даже после успешной установки производительность не всегда соответствует ожиданиям. На CPU ONNX Runtime может работать заметно медленнее, чем альтернативные решения, а на GPU ускорение не всегда включается автоматически и требует ручной настройки. Первые запуски моделей часто занимают больше времени, чем последующие, что создаёт ощущение нестабильности. В результате библиотека, которая должна была быть лёгким и быстрым решением для инференса, нередко воспринимается как тяжеловесный и требовательный инструмент, требующий значительных усилий для достижения приемлемой скорости работы.

### TensorFlow (далее TF) ###

Задача с TF в нашем проекте была заключена в том, чтобы ускорить работу программы, т.к скорость для нас была приоритетнее точности. TF по скорости сравнивали с Coffe, ONNX Runtime и OpenCV. 

Для TF нет готовой собранной библиотеки на C++, как у OpenCV, например. Данная библиотека изначально была написана на Python, который имеет не самую высокую скорость, однако мы все равно решили протестировать скорость ее выполнения. Проверяли не на Python, а с помощью API на языке C.

После сборки библиотеки и тестов на определение объекта на 1 фотографии было принято решение не использовать в дальнейшей работе TF по след. причинам:

1. Сборка библиотеки вручную на C API проблематичная
2. Скорость довольно медленная, по сравнению с OpenCV (1,6 против 1 секунды)
3. Потеряли бы много времени на исследование C API (изначально был написан неплохой код на C++ yolov5m, который стабильно хорошо работал)

## Qt GUI Interface ##

Проект теперь включает графический интерфейс на Qt 6.10.1, который позволяет удобно использовать систему компьютерного зрения через пользовательский интерфейс.

### Возможности интерфейса:

1. **Выбор модели**: Поддержка двух моделей YOLO:
   - YOLO11 (датасет COCO) - распознает 80 классов объектов
   - YOLOv5 (датасет LVIS) - распознает более 1000 классов объектов

2. **Выбор папки с изображениями**: Интерфейс позволяет выбрать папку с фотографиями для пакетной обработки

3. **Настройка выходной директории**: Возможность указать, куда сохранять обработанные изображения с результатами детекции

4. **Визуализация результатов**:
   - Просмотр оригинальных и обработанных изображений
   - Отображение найденных объектов с bounding boxes
   - Информация о времени обработки и классах объектов
   - Автоматическое распределение изображений по папкам по классам

5. **Прогресс обработки**: Отображение прогресса обработки изображений в реальном времени

### Сборка и запуск:

1. **Установите Qt 6.10.1**
2. **Установите OpenCV, совместимый с вашим компилятором:**
   - Если используете MinGW в Qt Creator: скачайте [OpenCV-MinGW](https://github.com/huihut/OpenCV-MinGW-Build)
   - Если используете MSVC: установите стандартный OpenCV для Windows

3. **Настройте OpenCV (автоматически или вручную):**
   - Запустите `setup_opencv.bat` или `setup_opencv.ps1` для автоматической настройки
   - Или установите переменную окружения `OpenCV_DIR` вручную

4. **Откройте проект в Qt Creator** (файл `UI/CMakeLists.txt`)
5. **Выберите подходящий CMake preset:**
   - `mingw-opencv`: для MinGW с OpenCV-MinGW
   - `mingw-opencv-alt`: для MinGW с OpenCV-MinGW в альтернативной папке
   - `msvc-opencv`: для MSVC с стандартным OpenCV

6. **Если нужно, настройте пути:**
   - Убедитесь, что пути к моделям YOLO корректны в `ComputerVisionWrapper::initialize()`

7. **Соберите и запустите проект**

### Решение проблем с OpenCV:

Если получаете ошибку "OpenCV Windows Pack has no binaries compatible with your configuration":

**Вариант 1: Использовать MinGW-совместимый OpenCV**
```bash
# Скачайте и распакуйте OpenCV-MinGW
# Установите OpenCV_DIR в CMake: C:/path/to/opencv-mingw/x64/mingw/lib/cmake/opencv4
```

**Вариант 2: Переключиться на MSVC компилятор**
- В Qt Creator: Tools → Options → Kits → Desktop (default) → Compiler → Microsoft Visual C++ Compiler
- Раскомментируйте соответствующие строки в `CMakeLists.txt`

**Вариант 3: Собрать OpenCV из исходников**
```bash
cd C:/opencv/sources
mkdir build_mingw && cd build_mingw
cmake -G "MinGW Makefiles" ..
mingw32-make -j4
mingw32-make install
```

### Универсальный постпроцессинг ###

- Реализован автоматический анализ формата выхода модели
- Программа сама определяет размерности данных и порядок измерений
- Универсальная функция преобразования данных работает с любым форматом выхода
- Автоматическое определение наличия objectness на основе количества признаков
- Динамическое вычисление количества классов и смещений в данных
- Адаптация к любому количеству классов в датасете
- Работает с любым форматом выхода YOLO независимо от версии
- Автоматически адаптируется к количеству классов (80 для COCO, 1203 для LVIS)
- Поддержка моделей с objectness (YOLOv5) и без (YOLO11)
- Устойчивость к изменениям в формате экспорта ONNX

### Параметризация инференса ###

- Параметры инференса вынесены в отдельную структуру
- Параметры передаются в функции обработки, а не берутся из глобальных констант
- Каждая модель может иметь свои индивидуальные настройки порогов
- Гибкость настройки порогов для разных датасетов
- Легкая адаптация к требованиям конкретной модели

- Использование современных функций ограничения значений
- Дополнительная проверка на минимальный размер рамки
- Более надежная обработка граничных случаев
- Предотвращение создания некорректных рамок
- Более стабильная работа с изображениями разных размеров

- Все пути вынесены в константы в начале программы
- Легкое изменение путей без изменения основной логики
